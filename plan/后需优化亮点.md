# 一、Theme A：智能体编排重新包装（创新性核心）

## 🔥 A1. 5-Agent 协作图

### 改造意图

赛道叫「大模型与**智能体**产业场景创新赛」，但现有产品语言全是「工作流」。需要把同样的 14 个 Dify 工作流"换个讲法"——抽象为 5 个 Agent 的协作系统。这是一次**框架重命名 + 一张拓扑图**的工作，几乎不写新逻辑，但直接踩中赛道关键词。

### 5-Agent 映射表

| Agent     | Emoji | 包含的工作流                          | 职责一句话           |
| --------- | ----- | ------------------------------- | --------------- |
| 导师 Agent  | 🎓    | growth1, growth2                | "我帮你规划 14 天怎么走" |
| 陪练 Agent  | 🤝    | practice1, practice2, practice3 | "我陪你练到会为止"      |
| 考官 Agent  | 📝    | wf11, wf13, wf14, wf15          | "我决定你能不能上岗"     |

| 分析师 Agent | 📊    | dashboard, query1, query2       | "我告诉店长哪里出了问题"   |

## 🔥 A2. Agent 实时调用链路侧边栏

### 改造意图

让评委**看见 Agent 在干活**。用户每次触发陪练 / 在岗助手 / 查询时，右下角浮出一个气泡，实时显示当前 Agent → 工作流 → 命中知识源 → 耗时。

### 视觉效果

```
                                      ┌─────────────────────────────┐
                                      │ 🤝 陪练 Agent  在工作中...    │
                                      │ ▸ practice1 (1.2s)          │
                                      │ ▸ 命中知识：嫌贵处理话术      │
                                      │ ▸ 输出评分：78 分 → +6 分    │
                                      └─────────────────────────────┘
```

### 改造点

| 文件                                  | 改动        | 详情                                                                  |
| ----------------------------------- | --------- | ------------------------------------------------------------------- |
| `backend/routers/agents.py`         | 编辑        | 新增 `GET /api/agents/activity-stream`（SSE 单向推送）                      |
| `backend/logging_config.py`         | 编辑        | 在 request_id 链路日志里抽取 Agent 调用事件，推到 SSE 队列                           |
| `frontend/js/agent-activity.js`     | 🆕 新建（**强制**） | 全局气泡组件 + SSE 订阅。导出 `mountAgentActivityPanel()`，启动时挂载到 body         |
| `frontend/styles/agent-activity.css`| 🆕 新建     | 气泡浮窗样式 + 进入/退出动画（不要塞进 `styles.css`）                                 |
| `frontend/js/app.js`                | 编辑（**仅 2 行**） | 加 import + 启动时调一次 `mountAgentActivityPanel()`                       |

### 技术细节

- **不用 WebSocket，用 SSE**：单向推送够用，FastAPI 原生支持，前端 `EventSource` 一行代码搞定
- 复用现有 `request_id` 链路日志，不新增日志层

### 加分点

- ✅ 演示时"右下角小窗"是评委记忆点
- ✅ 体现"多 Agent 协作"不只是 PPT 概念

# 二、Theme B：知识反哺闭环（业务价值核心）

## 🔥 B1 + B2. 高频问题 → 自动生成训练任务

### 改造意图

PRD 第 5.1 节承诺过"内容资产可复用"，但目前在岗助手的提问数据只是历史记录，没有反哺训练。**这是当前作品业务闭环的最后一公里**，做完整个故事就闭上了。

### 工作流

```
导购在岗助手提问 ───────► 客服 Agent 回答 + 记录
                                │
                                ▼
                       knowledge_feedback_service
                       (每天凌晨聚类高频问题)
                                │
                                ▼
                  店长首页"AI 教练建议"卡片
                  「本周顾客最常问『钻石培育钻和天然钻区别』
                   （被问 47 次），建议派发针对性陪练」
                                │
                                ▼
                       店长点【一键派发】
                                │
                                ▼
                  导购首页"待办任务"区域出现新任务
```

### 改造点

| 文件                                      | 改动        | 详情                                                                              |
| --------------------------------------- | --------- | ------------------------------------------------------------------------------- |
| `backend/knowledge_feedback_service.py` | 🆕 新建     | 用 TF-IDF + 关键词聚类（不调 LLM，秒级返回）                                                   |
| `backend/routers/knowledge_feedback.py` | 🆕 新建     | `GET /api/knowledge-feedback/clusters`、`POST /api/knowledge-feedback/dispatch`  |
| `frontend/js/knowledge-feedback.js`     | 🆕 新建（**强制**） | 店长首页"AI 教练建议"卡片 + 一键派发 + toast。导出 `mountKnowledgeFeedbackCard(container)`     |
| `frontend/js/app.js`                    | 编辑（**仅 2 行**） | 加 import + 店长首页路由里调一次 `mountKnowledgeFeedbackCard()`                          |
| `backend/seed_demo_data.py`             | 编辑        | 给演示数据加 200+ 条 assistant_records 模拟历史问答                                          |

### 加分点

- ✅ PRD 写过但未做的承诺 → 业务价值
- ✅ "系统能自我进化"的强故事 → 创新性
- ✅ 演示视频里一个完整闭环 → 演示效果

# 五、改造文件汇总（一眼看到所有改动）

## ⚠️ 前端强制总则：一功能一文件

> `frontend/js/app.js` 当前 **24,484 行**（已从 19,989 行增长），再加东西必失控。

> `app.js` 只允许做 3 件事：① 加 import ② 加路由分发 1 行 ③ 加菜单项 1 条。

### 模块约定（每个新 JS 文件都要遵守）

1. **单入口**：每个文件只导出 1 个对外接口，命名约定 `render<Feature>(container, props)` 或 `mount<Feature>()`
2. **不挂全局**：所有内部状态写在模块作用域内，不污染 `window.*`
3. **单文件 < 500 行**：超了就再拆子模块
4. **样式同步拆分**：单功能样式 > 50 行 → 拆独立 css 文件
