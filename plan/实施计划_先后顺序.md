### 模块约定（每个新文件都要遵守）

1. **自包含**：只导出 1 个对外接口，命名约定 `render<Feature>(container, props)`
   
   ```js
   // frontend/js/agent-orchestration.js
   // 非模块环境：window.AgentO = window.AgentO || {};
   //              window.AgentO.renderAgentOrchestration = function(...) {...}
   export function renderAgentOrchestration(container) { ... }
   ```

2. **不污染全局**：所有内部状态、辅助函数都包在模块作用域内，不挂 `window.*`（除非沿用现有命名空间）

3. **不修改 `app.js` 已有函数**：`app.js` 只新增 1 行 import + 1 行路由分发调用

4. **样式同步拆分**：如该功能样式 > 50 行，新建 `frontend/styles/<feature>.css` 与 JS 同名

5. **`index.html` 注册顺序**：新文件统一放在 `app.js` **之前** 引入

### `app.js` 的改动边界

`app.js` 在本次改造里**只允许做 3 件事**：

- 加 `import` 或 `<script>` 注册新模块（每个功能 1 行）
- 在路由表 / hash 监听器加 1 行分发
- 菜单项数组加 1 条目（如果新功能有侧边栏入口）

### 验收口径（每个 Phase 结束自查）

- [ ] 新功能的 JS 代码 **0 行** 出现在 `app.js`
- [ ] `git diff app.js` 看到的只有 import + 路由分发 + 菜单注册
- [ ] 新模块文件单文件 **< 500 行**，超过就再拆子模块
