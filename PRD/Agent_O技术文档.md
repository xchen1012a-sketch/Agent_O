# Agent_O 技术文档

## 1. 技术概述

Agent_O 采用前后端分离架构，前端为单页应用，后端为 FastAPI 服务，智能能力由 Dify 工作流、知识库检索和本地业务逻辑共同组成。系统围绕“训练、考核、成长、经营、治理”五类业务形成统一服务层。

## 2. 技术栈

- 前端：HTML、CSS、原生 JavaScript、Tailwind、ECharts、Flatpickr。
- 后端：Python、FastAPI、Pydantic、SQLite、SQLAlchemy。
- 智能层：Dify 工作流、知识库检索、业务规则编排。
- 语音层：TTS 接口与数字人能力。
- 测试：前后端均有较完整的自动化测试覆盖。

## 3. 架构分层

### 3.1 表现层

- 单页应用负责导航、页面渲染、表单交互、状态切换和数据展示。
- 移动端与桌面端使用同一套核心逻辑，样式做响应式适配。

### 3.2 接口层

- FastAPI 统一暴露业务接口。
- 登录、用户信息、任务、训练、考核、知识库、分析、审计、设置均由路由模块提供。

### 3.3 业务层

- 训练周期、成长计划、评估评分、查询解析、知识反馈、EVO 进化逻辑在业务服务中实现。

### 3.4 数据层

- SQLite 为主要持久化存储。
- 使用表结构保存用户、门店、任务、训练记录、考核记录、知识库元数据和审计数据。

### 3.5 智能编排层

- 通过工作流注册表统一管理 Dify workflow code、路由路径、调用类型和 Agent 角色。
- 支持工作流健康检查与配置状态汇总。

## 5. 工作流注册机制

系统通过统一注册表维护工作流元数据，字段包括：

- code
- label
- api_key_env
- route_path
- call_type
- agent_role

这样可以让健康检查、配置检查、接口调用和 Agent 拓扑保持一致。

## 6. 前端结构

- `index.html` 提供工作台壳和登录页。
- `js/app.js` 负责路由、页面切换、数据请求和主交互。
- `styles.css` 负责整体视觉系统、排版和响应式规范。
- `styles/*.css` 负责细分模块样式。
- 资源中集成了 ECharts、Flatpickr、Three.js 模型和数字人视觉能力。

## 7. 数据与接口特征

- 接口输出统一采用 JSON。
- 关键业务页面依赖结构化返回，便于前端渲染。
- 训练、考核、成长、分析结果可以反向写入记录表。
- 日志中保留 request id、route、workflow code、耗时和状态码，便于排查。

## 8. 部署与运行

- 后端启动后挂载 `/frontend/` 静态资源。
- 根路径自动重定向到前端工作台。
- 健康检查包括数据库和 Dify 配置。
- 可通过上传受限 `.env` 文件动态更新运行时配置。

## 10. 技术风险控制

- 对外输入做校验和脱敏。
- 关键配置做白名单限制。
- 失败场景提供本地回退。
- 统一审计可追踪。
- 合规内容不越界到鉴定、法律和投资承诺。
