# 智能体编排架构说明

Agent_O 将珠宝零售培训中的 14 条核心 Dify 工作流抽象为 5 个业务 Agent。前端通过 `#agent-orchestration` 展示拓扑图，后端通过 `/api/agents/topology` 输出同一份映射数据，并通过 `/api/agents/activity-stream` 把真实工作流请求推送成实时调用气泡。

## 5-Agent 映射

| Agent | 核心工作流 | 业务职责 |
| --- | --- | --- |
| 导师 Agent | growth1, growth2 | 规划 14 天成长路径，生成学习任务并给出阶段复盘。 |
| 陪练 Agent | practice1, practice2, practice3 | 发起实战对练、输出评分、更新能力画像。 |
| 考官 Agent | wf11, wf13, wf14, wf15 | 完成盲盒考核、标准出卷、阅卷和自动晋级解锁。 |
| 客服 Agent | assistant1, assistant2 | 支持导购应对真实顾客，沉淀一线服务话术。 |
| 分析师 Agent | dashboard, query1, query2 | 汇总训练和经营数据，识别风险并给出管理建议。 |

## 协作链路

用户输入训练目标、顾客问题或经营查询后，系统按任务类型交给导师、陪练或考官 Agent。三类训练结果汇总给分析师 Agent，形成风险识别、能力短板和经营建议；分析师输出再回流给客服 Agent，让导购在真实服务场景中得到即时支持。

## 演示话术

这不是单个聊天机器人，而是一个面向珠宝零售培训的 5-Agent 协作系统。导师负责成长计划，陪练负责实战提升，考官负责上岗门槛，分析师负责管理洞察，客服负责一线支持。14 条 Dify 工作流在后台被编排成稳定的业务闭环。

右下角的 Agent Activity 气泡来自 SSE 事件流。每次用户触发陪练、在岗助手、经营查询、成长计划或考核工作流时，请求中间件会把 route、workflow_code、Agent 角色、耗时、request_id 和知识源推到前端，评委能看到“哪个 Agent 正在调用哪条工作流”。

## 技术落点

- `backend/workflow_registry.py`：统一维护工作流注册表、Agent 角色和拓扑边。
- `backend/agent_activity.py`：维护 Agent 活动事件队列、历史缓存和 route 到 workflow 的映射。
- `backend/routers/agents.py`：提供 `/api/agents/topology` 和 `/api/agents/activity-stream`，返回拓扑数据并输出 SSE 实时事件。
- `backend/main.py`：请求中间件在已注册工作流 API 完成后发布 Agent 活动事件。
- `frontend/js/agent-orchestration.js`：使用 ECharts graph 渲染拓扑图，点击 Agent 节点显示包含的工作流。
- `frontend/js/agent-activity.js`：挂载全局 Agent Activity 浮窗，订阅 SSE 并渲染实时调用气泡。
- `frontend/styles/agent-orchestration.css`：负责桌面和移动端布局、暗色模式、加载态和低动效支持。
- `frontend/styles/agent-activity.css`：负责右下角实时气泡、折叠态、暗色模式和低动效支持。
